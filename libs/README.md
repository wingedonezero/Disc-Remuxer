# libs — our libraries

edited directly whenever the program needs different behaviour; nothing is
kept as a patch series. The first commit of each library is the unmodified
upstream release, so `git log -- libs/<name>` / `git diff <first commit> --
libs/<name>` show every change we made.

## How they are built

`./build.sh [debug|release]` builds everything (the top `Makefile`, the rules
in `mk/*.mk`): every library into `build/<mode>/`, only the finished programs
(`ffmpeg`, `ffprobe`, `ccextractor`, our program) into `dist/<mode>/`.
The tests (`./build.sh test`, `tests/`) link the same static libraries into
their bridge (`mk/test.mk`).

- libdvdcss, libdvdread, libdvdnav: compiled directly (`mk/dvd.mk`); the
  `config.h` each one's `meson.build` would generate on Linux is written by
  the build. libdvdread links libdvdcss directly (no `dlopen`).
- expat: compiled directly (`mk/expat.mk`); `expat_config.h` is written with
  the values expat's `configure` gives on Linux / glibc (its defaults:
  `XML_DTD`, `XML_GE`, `XML_NS`, `XML_CONTEXT_BYTES` 1024).
- libgpg-error, libgcrypt, libaacs: each with its own `configure` + `make
  install`, out of tree in `build/<mode>/`, static libraries; libgcrypt on
  our libgpg-error, libaacs on both (their install folders given to the next
  `configure`); the autotools are never run again (`mk/aacs.mk`).
- CCExtractor: its own CMake (`WITHOUT_RUST=ON`: C only, no OCR / FFmpeg /
  sharing), on a copy of `ccextractor/src` in `build/<mode>/` (its CMake
  writes a header into the source tree); the `ccextractor` program goes to
  `dist/<mode>/`, next to ours, and runs as a helper process for closed
  captions (its error path ends its process, and its decoder state is
  global).
- FFmpeg: its own `configure` + `make`, out of tree in `build/<mode>/`,
  static libraries, autodetection off (every external library is enabled by
  name), DVD-Video demuxer (FFmpeg's own, unchanged) on libdvdnav / libdvdread
  (with our changes 140-158; DVD is being rebuilt as a part of the disc layer). The `ffmpeg` and
  `ffprobe` programs go to `dist/<mode>/` for testing.
